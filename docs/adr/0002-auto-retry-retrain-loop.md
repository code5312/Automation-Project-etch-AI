# ADR-0002: 재학습(C8)을 "1회 완주"에서 "자동 반복(최대 4회)" 구조로 변경

- 날짜: 2026-11-02
- 상태: 승인(사용자 결정 2026-11-02)
- 배경: 기존 정의서 §3 증거②·설계서 C8은 "드리프트 감지 → 재학습 → 게이트 → 1회 완주"였다.
  사용자 결정으로, 게이트를 통과할 때까지(상한 안에서) 사람 개입 없이 자동으로 재시도하는
  구조로 바꾼다.
- 영향 문서: `project-definition.md` §3·§7.4·§13, `project-design.md` §2·C8·§15,
  `project-checklist.md` 핵심 증거 추적·6주차.

## 변경 내용

### 에스컬레이션 단계 (최대 4회 시도, [제안] — 실측 전까지 수치는 가정값)

| 시도 | 데이터 | 학습 | ViennaPS 재호출 여부 |
|---|---|---|---|
| 1 | 드리프트 train 40개(최초 생성분) | champion에서 3~5에폭 미세조정 | 아니오(최초 생성은 트리거 시 1회) |
| 2 (1 BLOCK 시) | 드리프트 train 40→100개로 확장 | 동일 설정 재학습 | **예** — 추가 60개 시뮬레이션 |
| 3 (2 BLOCK 시) | 100개 그대로 | 에폭 10~15로 증가 | 아니오 |
| 4 (3 BLOCK 시) | 100개 그대로 | 학습률 조정(예: ×0.5) | 아니오 |

- 각 시도 후 `golden_drift`+`val`로 게이트 재평가. **PASS면 그 시도에서 즉시 승격, 루프 종료.**
- 4회 모두 BLOCK이면 자동 루프 종료, 기존 champion 유지 + 알림 로그. 사람이 사후 원인
  분석을 할 수 있지만, 이는 다음 드리프트 사이클을 위한 검토이며 **이번 루프 실행 자체는
  "사람 개입 없음" 정의를 유지한다**(설계서 §15 결정 근거 참조).
- 전체 시도 로그는 `reports/evidence/retrain_<ts>.json`의 `attempts: [{attempt, config, gate_result}, ...]`에 기록(W6-05).

### 변경 전/후 비교

| 항목 | 변경 전 | 변경 후 |
|---|---|---|
| 증거② 기준 | "사람 개입 없이 **1회** 완주" | "사람 개입 없이 **자동 반복(최대 4회) 포함** 완주" |
| BLOCK 시 대응 | 사람이 수동으로 train 수·에폭·학습률 조정 후 재실행 | 동일한 조정을 **자동 에스컬레이션**이 순서대로 시도 |
| ViennaPS 호출 시점 | 트리거 시 1회(60개 생성) | 트리거 시 1회(60개) + **2차 시도에서 1회 추가(+60개)**, 그 이후는 재호출 없음 |

## 이유

- 사용자 요청(2026-11-02): "5번 재학습은 될 때까지 자가적으로 학습하는 구조로" — 평가·게이트
  기준에 도달할 때까지 사람이 매번 수치를 조정해 재실행하는 수동 과정을 자동화해, 증거②가
  보여주는 자동화 수준을 높인다.
- 무한 반복은 CPU-only·8주 일정에서 비현실적이라 **상한 4회**로 제한한다(스파이크 시간상자와
  같은 철학: 상한 안에서 안 되면 멈추고 보고한다).

## 대안(기각)

- 기존 "1회 완주 + 실패 시 사람이 수동 조정" 유지 — 사용자가 자동화 수준을 더 높이길 원해 기각.
- 상한 없는 무한 재시도 — 자원·시간 예산 초과 위험으로 기각.
