# ADR-0007 등록된 FNO의 서빙과 롤백

상태 [제안]

기존 레지스트리는 모델 카드의 가중치 해시를 검증하고 `current` 포인터로 champion을 지정한다. FNO는 가중치와 함께 입력 정의, SDF 전처리, 추론 구현도 필요하다. 서빙은 격리 검증에서 이 네 파일을 묶어 로드했다.

## 결정

- 모델 카드에 `config.model_family`가 없으면 MGN으로 해석한다. FNO의 파일은 `runs/retrain/<model_id>/`에 보관하고, `config.artifact_files_sha256`에 `model.safetensors`, `config.json`, `inference.py`, `preprocess.py`의 SHA-256을 기록한다. 레지스트리가 발행 전에 네 파일을 검증하고, 서빙 로더도 모델을 읽기 전에 대조한다.
- 기존 예측 요청의 레시피 키는 계속 받는다. 선택 필드 `substrate_a_ie`가 들어오면 FNO 입력으로 전달한다. 생략하면 카드의 `nominal_substrate_a_ie`를 사용한다. 예측 응답 구조는 동일하다.
- API 요청은 시작할 때 champion 하나를 선택한다. 다음 요청은 레지스트리 포인터가 바뀌면 다시 로드한다. 새 후보를 등록할 때 검증 기준으로 사용한 champion의 ID를 전달할 수 있으며, 그 ID가 달라졌으면 등록을 거절한다.
- 레지스트리 쓰기 작업은 한 로컬 저장소에서 직렬로 수행하고, `current`는 같은 디렉터리의 임시 파일에서 원자적으로 교체한다. 모델 번들 파일과 모델 ID는 등록 이후 동일하게 유지한다.

## 검증 범위

승격·실제 HTTP 추론·롤백은 로컬 Docker와 격리된 레지스트리에서 검증한다. 자동 재학습 워커가 어떤 절차로 새 후보를 만드는지와 실제 운영에 배포하는 결정은 별도 검토 대상이다.
