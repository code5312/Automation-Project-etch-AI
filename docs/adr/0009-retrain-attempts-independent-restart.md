# ADR-0009: 재학습 시도 간 독립 재시작(champion에서 매번 fresh-restart) 유지

- 날짜: 2026-11-25
- 상태: **승인(사용자 결정 2026-11-25 — 팀 전체 합의 없이 사용자 단독 결정으로 진행,
  "팀 동의 안해도 돼")**
- 영향 파일: 없음(동작 변경 없음) — `docs/project-checklist.md` W9-05,
  `src/etchpipe/retrain/loop.py` 독스트링에 결정 근거만 명시.
- **범위**: `run_retrain_loop`의 시도 간 체크포인트 승계 여부만 다룬다. 시도 내부
  동작(에폭별 베스트 체크포인트 선택)은 ADR-0006, GPU 사용 여부는 ADR-0008 — 둘 다
  이 결정과 독립.

## 배경

`retrain/loop.py::run_retrain_loop`는 매 시도(`ATTEMPTS`의 최대 4개 설정)마다
`fine_tune_fn(champion_ckpt, cfg)`를 호출한다 — `champion_ckpt`는 루프 진입 시 고정된
값으로, 시도 2·3·4도 시도 1의 결과가 아니라 **항상 원본 champion에서** 다시
미세조정한다. 이게 ADR-0002가 명시적으로 결정한 사항은 아니었다 — ADR-0002의
에스컬레이션 표는 "데이터 크기·에폭·학습률을 단계적으로 올린다"만 정했고, "이전 시도
결과를 이어받을지"는 코드가 암묵적으로 정한 것이었다. `docs/project-checklist.md`
W9-05는 이 암묵적 선택을 명시적 결정으로 바꾸기 위해 만들어졌다.

ADR-0006(W9-03)에서 진단했던 attempt 3 성능 악화는 "①매 시도 독립 재시작 + ②베스트
체크포인트 선택 없음"의 **조합**이 원인으로 지목됐었다 — ①은 그대로 두고 ②만
ADR-0006에서 고쳤다. 이번 ADR은 ①을 그대로 유지할지 재검토하는 자리다.

## 결정

**독립 재시작(현재 동작)을 유지한다. 코드 변경 없음.**

이유:

1. **게이트를 통과하지 못한 상태 위에 쌓지 않는다** — 시도 N이 BLOCK됐다는 건
   `gate_fn`(레시피 통과율·물리·회귀 검정)이 그 가중치를 거부했다는 뜻이다. 시도 N+1이
   그 위에서 이어 학습하면, 검증되지 않은(거부된) 상태를 다음 시도의 출발점으로
   삼게 된다 — 각 시도를 "champion 대비 독립적인 가설 검증"으로 유지하는 쪽이 원인
   분석과 신뢰성 면에서 더 안전하다.
2. **에스컬레이션 표 자체가 "독립 가설 비교"로 설계돼 있다** — 시도 2(데이터 확장),
   시도 3(에폭 증가), 시도 4(학습률 감소)는 서로 다른 단일 변수를 바꿔보는 구조다.
   누적 학습으로 바꾸면 시도 3·4의 효과가 "그 단일 변수 변경" 때문인지 "이전 시도들이
   누적된 학습" 때문인지 뒤섞여, 사후에 어떤 조정이 실제로 유효했는지 분석하기
   어려워진다.
3. **ADR-0008(W9-04)로 재학습 시간 자체가 거의 해소됐다** — 누적 학습의 주된 이점은
   "이전 시도의 학습을 버리지 않아 시간을 아낀다"인데, GPU 지원(실측 92.9배, W8-09)이
   들어온 지금은 이 절감 효과가 작다. CPU 전용이었던 2026-11 초 시점에는 더 설득력
   있는 주장이었겠지만, 지금은 독립 재시작의 단점(중복 계산)이 크지 않다.
4. **ADR-0006이 이미 '마지막 에폭 과적합'을 고쳤다** — 애초 attempt 3 악화의 두
   원인 중 하나는 이미 해소됐다. 남은 독립 재시작 자체가 추가 위험을 만든다는 근거는
   없다(오히려 위 1·2가 안전장치로 작동).

`src/etchpipe/retrain/loop.py::run_retrain_loop` 독스트링에 이 결정(ADR-0009)과
근거를 한 줄 추가해, 다음에 코드만 보고 "왜 champion_ckpt를 매번 그대로 넘기지?"라고
다시 조사하지 않도록 한다.

## 비용·트레이드오프

- 포기하는 이점: 시도 간 학습 누적으로 더 빠르게 게이트를 통과할 가능성(특히 시도
  1이 거의 통과선에 가까웠던 경우) — 이번 결정으로 그 가능성은 포기한다[제안, 실측
  근거 없음 — 실제로 그런 경계 사례가 나온 적은 아직 없음].
- GPU 지원 이후 시간 비용이 낮아졌다는 근거(결정 3)는 "별도 하네스의 92.9배
  실측"(W8-09)이지 "이 코드 경로로 재확인된 수치"는 아니다(W9-04 증거의 미확인
  항목과 동일) — GPU 통합 실행이 재확인되면 이 근거도 같이 재검증해야 한다.

## 대안 (기각)

- **누적 학습으로 전환**: 위 결정 1·2의 이유로 기각 — 검증 안 된 상태 위에 쌓는 리스크,
  원인 분석 어려움.
- **시도별로 선택(처음 1~2회는 독립, 이후엔 누적 등 혼합)**: 에스컬레이션 표 자체를
  더 복잡하게 만들고, 그 복잡성을 정당화할 실측 근거(경계 사례)가 아직 없다 — 기각,
  필요해지면 재검토.
