# 프로젝트 정의서: 식각 공정 AI 대리 모델의 검증·재학습 자동화 파이프라인

- 부제: ViennaPS 기반 데이터 생성부터 회귀 게이트·배포까지의 MLOps 워크플로우
- 개발: 8주
- 버전: v0.1 (초안, 인터페이스 동결 전 — CLAUDE.md 작업규칙 6)
- 용도: 취업 포트폴리오 + 팀 프로젝트 제출·발표
- 관련 문서: `project-design.md`(구현 사양), `project-checklist.md`(일정·작업)
- 표기: **[확인]** 실행으로 검증됨 / **[제안]** 변경 가능한 설계 값 / **[미확인]** 검증 전, 사실로 쓰지 않음

## 1. 정의

식각 공정 AI 대리 모델의 데이터 생성 → 학습 → 평가 → 회귀 게이트 → 배포를 자동화한다. 기준 오차를 넘는 모델은 자동 차단하고, 조건 변화 시 재학습·재평가를 거쳐 게이트 통과 시에만 교체한다. 통과하지 못하면 기존 모델을 유지한다.

## 2. 배경

- NVIDIA 블로그(AI-Physics TCAD)는 SK하이닉스가 식각용 GNN 계열(GNS) 대리 모델을 PhysicsNeMo 기반으로 개발한다고 공개했다.
- 블로그 미공개 항목: 정답 시뮬레이터 이름, 모델 입출력, 손실 식, 데이터셋 크기, 정확도·속도 수치, 코드·가중치. 개선 요소(Chamfer 손실, 매 스텝 리메싱, 특징 선택, 멀티스케일 메시지 전달, 재료 특징 갱신)는 정성적으로만 언급됨.
- 블로그 레퍼런스 레시피는 와류(vortex shedding) CFD 예제이며 식각 전용이 아니다.
- 본 프로젝트는 공개된 접근 방식을 참고해 오픈소스 시뮬레이터로 직접 구성한다. 재현이 아니며, SK하이닉스 수치와 비교하지 않는다.
- 모델의 새로움은 주장하지 않는다. 차별점은 대리 모델 수명주기(생성·검증·교체)의 자동화와 그 실행 증거다.

## 3. 합격 기준 (증거 2개)

| 증거 | 합격 기준 (실행 로그로 제시) |
|---|---|
| ① 회귀 게이트 차단 | 정상 모델 통과 / 의도적으로 망가뜨린 모델 CI 차단 / 데이터 해시·골든셋 변조 차단 (세부 6종 테스트는 설계서 §3 C5·체크리스트 W5-06) |
| ② 재학습 루프 완주 | 가상 드리프트 투입 → 데이터 생성 → 재학습 → 평가 → 게이트 → 교체가 사람 개입 없이 1회 완주, 재학습 전/후 오차와 교체 결과 로그 |

- 모델 품질 요건: 정상 모델과 망가진 모델이 구분될 정도 [제안]
- "조건 변화"는 시뮬레이터 계수를 바꾼 가상 드리프트다.

## 5. 범위

### 5.1 필수
- 시나리오: 2D 트렌치 식각 1종 (SF6/O2, Si + 마스크)
- 정답 데이터: ViennaPS
- 모델: A = MeshGraphNet(그래프), B = FNO(격자), 단순 베이스라인
- 자동화: 내용 해시 데이터 버전, 학습, 평가, 회귀 게이트, 레지스트리, 서빙 API, 재학습 트리거
- 시뮬레이션 스윕: Kubernetes Job(로컬 `kind` 1회 성공) + `xargs -P` 대체 경로 [제안]
- CI: 1주차부터 상시 적용
- 대시보드: 화면 3개 (레시피 입력→예측 / 예측 vs 정답·모델 비교 / 지표·게이트 이력) [제안]

### 5.2 선택 (필수와 증거 ①② 완료 후)
- 레시피 추천(장비 제어 없음), active learning, 비용 지표(추론 1회당 연산 시간), 가상 데이터 실시간 수집 시연(Kafka/MQTT)

### 5.3 제외
- 실제 장비 제어, 3D, KMC/MD 멀티스케일, 3D 디지털 트윈, 실제 팹 데이터
- 제외 기술: PhysicsNeMo Curator, ONNX/Triton, Slurm, MLflow, DVC, Transolver

## 6. 표현 규칙

- 대리 모델은 정밀 시뮬레이션의 보완이며 학습 범위 안에서만 유효하다.
- 입력은 레시피/플럭스 파라미터 + 마스크 형상이다. 센서값 직접 입력은 하지 않는다.
- 속도는 추론 지연만, 하드웨어·배치 조건과 함께 보고한다. 속도 이득은 미측정이다. [미확인]
- 가상 데이터만 사용하며 실제 팹 적용 결과를 주장하지 않는다.
- 금지 표현(코드 주석·README·대시보드 포함): "대체한다", "실시간", "실제 fab 데이터", "SK하이닉스 모델 재현", "어떤 AI가 효율적인지 입증"

## 7. 데이터

### 7.1 입력 변수 Θ (7개)
| 이름 | ViennaPS 파라미터 [확인] | 범위 [제안] |
|---|---|---|
| ion_flux | `ionFlux` | 3 ~ 30 (log) |
| etchant_flux | `etchantFlux` | 1350 ~ 13500 (log) |
| oxygen_flux | `passivationFlux` | 240 ~ 2400 (log) |
| ion_mean_energy | `Ions.meanEnergy` | 50 ~ 200 |
| ion_exponent | `Ions.exponent` | 100 ~ 1000 (log) |
| mask_width | `MakeTrench(trenchWidth)` | 6 ~ 14 µm |
| mask_height | `MakeTrench(maskHeight)` | 6 ~ 14 µm |

- 식각 시간은 입력이 아니라 스냅샷 순서다. 종횡비는 파생 값이다.
- 단위: µm, 분. 일부 레시피는 5분에 깊이 40µm 이상이므로 범위 축소 또는 목표 깊이 정지 조건을 도입한다. [확인: 현상 / 제안: 대응]

### 7.2 출력
- 시간 스텝별 표면 프로파일(2D 선분 메시 .vtp, 재료 정보 포함). 스냅샷마다 점 개수가 다름. [확인]
- 파생 지표: CD, 바닥 CD, 깊이, 테이퍼 각도, 보잉

### 7.3 규모·분할 [제안]
| 구분 | 레시피 | 용도 |
|---|---|---|
| train | 300 | 학습 |
| val | 40 | 검증 |
| test | 40 | 최종 평가 |
| OOD | 20 | 학습 범위 밖 평가 |
| golden | 10 | 회귀 게이트 (고정, 변경 금지) |

- 레시피 단위 분할, Sobol 샘플링(시드 고정), 레시피당 스냅샷 약 20장.
- 총량은 1주차 시간 측정 후 확정.

### 7.4 가상 드리프트
- 모델 입력 Θ에 없는 시뮬레이터 계수(Substrate.A_ie, 기본 7.0)를 ×1.15로 변경한 조건에서 레시피 60개 생성: train 40 / val 10 / golden_drift 10 [제안]

## 8. 시스템 구성


## 10. 사실 확인 현황

### 확인됨
- `ViennaPS==4.5.0` + `ViennaLS==5.8.5`에서만 import 성공(Python 3.13). 기본 설치 시 ViennaLS 5.9.0이 설치되어 실패.
- 스냅샷: Process를 짧은 duration으로 반복하고 매번 `domain.saveSurfaceMesh(path, addInterfaces=True)`. `MaterialIds`·`Normals`는 셀 데이터. pyvista로 읽음(meshio는 .vtp 불가).
- 시뮬레이션 5스텝(rays=300): 레시피별 약 3.8~37초. 5분 후 깊이 약 7~42µm.
- `nvidia-physicsnemo 2.2.2` MeshGraphNet은 PyTorch Geometric + torch_scatter 필수. torch_scatter는 `pip install --no-build-isolation torch_scatter`로 소스 빌드. 우리 그래프(노드 14, 엣지 3, 출력 2)는 CPU에서 forward/backward 동작, 학습 1스텝 약 40~180ms (노드 300~400개).
- PyPI torch 설치 시 CUDA 라이브러리 포함 약 10GB.

### 미확인
- 쿠버네티스(kind) Job 실행, `Dockerfile.sim` 빌드
- 다단계 롤아웃(예측 표면 재입력 20스텝) — 가장 불확실
- `MaterialIds` 0/10의 재료 의미
- FNO 구현·학습, 추론 속도, 속도 이득
- ViennaPS GPL-3.0이 배포에 미치는 영향에 대한 세부 법적 검토(대응 방침은 §11 라이선스 항목 참조)
- 학습·시뮬레이션 환경 공존 여부(기본은 분리)

## 11. 제약

- GPU 없음을 기본 가정. 서빙·테스트는 CPU에서 동작. 본 학습 자원은 미정.
- 환경 3개 분리: 시뮬레이션 / 학습·평가 / 서빙.
- 대용량 데이터(`data/raw`, `data/processed`, `.vtp`, 체크포인트)는 Git 제외.
- 비밀값은 환경변수·CI Secrets만. 의존성 버전 고정.
- 라이선스: 저장소 코드는 **Apache-2.0**. ViennaPS(GPL-3.0)를 포함하는 시뮬레이션 이미지(`docker/Dockerfile.sim`)에만 GPL-3.0 조건이 적용되며 해당 사실을 NOTICE에 별도 표기한다. ViennaPS는 분리된 시뮬레이션 환경에서 바인딩 호출로만 사용하고 본 리포지토리 코드에 정적 링크·포함하지 않는다. [제안, 사용자 결정 2026-10-27 — 법률 자문으로 확정된 사실은 아님]

## 12. 개발 방식

- 워킹 스켈레톤(더미 모델로 전체 선행) → 부품 단계 교체
- 위험 우선 스파이크 7개(W1-S0~S6, 상세는 설계서 §14 및 체크리스트 1주차): 환경 설치 / 시뮬레이션 시간·깊이 폭주 / 재현성 / 롤아웃 / 로컬 쿠버네티스 Job / 재료 매핑 / FNO 확인
- 칸반, 동시 진행 최대 2개. 주간 계획, 금요일 자기 데모, ADR
- CI 1주차부터. 지표·게이트는 테스트 먼저
- 완료 정의: 코드 + 테스트 + CI 통과 + 체크리스트에 실행 증거
- 일정: 1주 스파이크·뼈대 / 2주 스켈레톤 / 3주 실데이터·변환 / 4주 모델 A·롤아웃 판정 / 5주 평가·게이트·레지스트리(증거①) / 6주 모델 B·재학습·서빙(증거②) / 7주 대시보드·통합·점검 / 8주 문서·발표·예비
