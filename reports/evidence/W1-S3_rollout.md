# W1-S3: 모델 A 롤아웃 사전시험 — 방향 판정

- 목표: 레시피 3~5개로 소규모 과적합 후 다단계 롤아웃이 발산하는지 확인. **방향만 판정**(진행 가능/후퇴 필요).
- 시간 상자: 1시간(중간에 호스트 메모리 부족으로 환경 설치가 한 번 중단되어 재시도함 — 실제 계산 자체는 약 5~6분)
- 레시피: S1에서 가장 빠른 4개(ion_flux가 작아 식각이 느린 쪽)를 K=6(7개 스냅샷, step 0~6)으로 새로 실행. 시드 42(run_sim 기본), rays=300.
- 환경: ViennaPS/ViennaLS + PhysicsNeMo/PyG/torch_scatter를 **같은 Python 3.13 컨테이너에 함께 설치**해서 돌렸다(스파이크 전용 단축 경로 — 평소 설계 §6의 "환경 3종 분리"는 유지하되, 이번엔 한 스크립트로 시뮬레이션→ETL→학습→롤아웃을 잇기 위한 임시 조치). 부수적으로 **train 스택이 Python 3.13에서도 설치·import된다는 것**을 확인함(3.11에서만 확인했던 W1-03의 범위를 넘어선 추가 확인).

## 실행

`reports/evidence/W1-S3_rollout.py` 한 파일로 1)시뮬레이션 2)ETL(`etl.py`의 `load_snapshot`/`to_graph` 재사용) 3)과적합 학습 4)다단계 롤아웃을 순서대로 수행.

## 해석

- 4개 레시피 모두 **매 스텝마다 오차가 꾸준히, 거의 선형으로 증가**한다(폭발적/지수적 발산이나 NaN은 없음). step1→step6 오차가 약 5.6~6.3배로 커지는데, 이는 "한 스텝 예측 오차가 누적"되는 전형적 자기회귀 드리프트 패턴과 일치한다.
- 원인으로 보이는 것 두 가지(둘 다 이번 스파이크의 단순화 때문, 모델 구조 자체의 결함으로 보이지 않음):
  1. **학습이 충분히 수렴하지 않음**(위 loss 곡선) — teacher forcing·학습률 스케줄·더 많은 반복이 없어서 한 스텝 예측 자체도 완전히 맞지 않는다. 한 스텝 오차가 있으면 롤아웃에서 그대로 누적된다.
  2. **이번 스파이크는 연결(엣지)·법선을 롤아웃 내내 step 0 값으로 고정**했다(체크리스트 W4-05가 예정한 "엣지 재계산·법선 재계산"을 하지 않음). 위치가 바뀌는데 엣지 feature(상대 위치)는 안 바뀌니, 스텝이 진행될수록 입력 자체가 실제 지오메트리와 어긋나 오차를 키운다.
- 두 원인 모두 **W4(본 학습)에서 바로 고칠 수 있는 것**이고, 이번 스파이크의 의도적 단축(1시간 상자, 4레시피, 300회 학습, 연결 고정)의 결과로 보인다. 모델 구조(MeshGraphNet)나 접근 자체가 근본적으로 안 맞는다는 신호(NaN, 발산 폭주, 전혀 안 줄어드는 loss 등)는 없었다.

## 판정

**진행 가능(조건부)**: 폭발적 발산이 아니라 완만한 선형 누적 오차이고, 원인이 명확히 "이번 스파이크의 단순화"로 설명된다. 다만 그대로 두면 W4 본 학습에서도 같은 문제가 재현될 수 있으므로, W4-02/W4-05에서 반드시:
1. teacher forcing 또는 스케줄된 노이즈 주입(원 논문 MeshGraphNets 관례)로 단일 스텝 학습을 더 수렴시키기
2. 매 롤아웃 스텝마다 엣지·법선을 갱신(체크리스트에 이미 계획돼 있음)
을 적용하고 나서 재판정해야 한다.

## 대안

후퇴(최종 프로파일 1장 예측, W4-06 후퇴안)는 **아직 필요 없음** — 이번 결과가 "교정 가능한 원인에 의한 완만한 드리프트"로 보이기 때문. W4 말 D4 판정에서 teacher forcing+엣지재계산 적용 후에도 베이스라인(b)보다 못하면 그때 후퇴안을 검토.
