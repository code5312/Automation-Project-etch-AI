## 상태

- **대본 작성**: 완료(아래).
- **리허설 2회**, **백업 영상 녹화**: 사람이 실제로 말하고 화면을 조작하며 수행해야

  쓰지 않음]. **사용자가 GPU 환경에서 직접 진행하기로 결정**(2026-11-14) — 아래
  "리허설 기록표"는 그 실행 결과를 채우기 위한 템플릿으로 남겨 둔다.

## 왜 전부 라이브로 하지 않는가 [확인, 실측 근거]

5분 안에 4가지(정상 PASS·차단·재학습·대시보드)를 전부 라이브로 보여줄 수 없다 —
실측 소요시간이 이렇다:

| 파트 | 실측 소요시간 | 근거 |
|---|---|---|
| 게이트 부정 테스트 10종 | 약 13~15분 | README Quick Start, `reports/evidence/W5-09_gate_negative.md` |
| 재학습 루프(1차 시도 PASS여도) | 수 분~(BLOCK 반복 시) 수 시간 | `reports/evidence/W6-06_retrain_evidence.md`, `W7-07_pipeline_timing.md` |
| 대시보드 조작 | 수십 초 | 라이브 가능 |
| `/predict` 1회 호출 | 약 19~20초 | `reports/evidence/W6-10_docker_compose_local_run.md` |

그래서 **느린 두 파트(게이트·재학습)는 미리 녹화한 터미널 클립**을 재생하고, **빠른
대시보드 파트만 라이브**로 조작한다 — 이건 거짓 시연이 아니라 실제로 실행해서 남긴
증거 영상을 보여주는 것이다[제안, 시간 제약에 따른 선택].

## 사전 준비 체크리스트 (발표 하루 전)

- [ ] `ETCH_API_KEY=<키> docker compose up`으로 서빙+대시보드 기동, `localhost:8000` 접속 확인
- [ ] 클립 A 녹화: `python scripts/run_gate_negative.py` 전체 실행 화면에서
  **정상 모델 PASS 줄**과 **노이즈 모델 BLOCK 줄**이 나오는 순간만 15초 분량씩 잘라 둠
  (전체 13~15분을 다 보여주지 않음)
- [ ] 클립 B 녹화: 재학습 데모(`docker run ... etch-serve:0.1 python
  scripts/run_retrain_demo.py`) 실행 화면 중 **마지막 결과 출력**(`promoted=True`,
  `registry/current` 변경) 부분만 20초 분량 잘라 둠
- [ ] 클립 A/B를 발표 노트북에 미리 복사(인터넷 연결 없이도 재생 가능하게)
- [ ] 대시보드 3화면이 전부 열리는지, `/predict` 응답이 20초 내로 오는지 직접 1회
  확인(네트워크·서버 상태 당일 변수 제거)

## 백업 영상 녹화 가이드
