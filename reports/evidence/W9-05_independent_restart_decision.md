# W9-05: 재학습 시도 간 누적 학습 여부 (ADR-0009)

## 1. 문제

`retrain/loop.py::run_retrain_loop`는 매 시도(최대 4회)에 고정된 `champion_ckpt`를
그대로 넘겨, 시도 2·3·4도 시도 1의 결과가 아니라 항상 원본 champion에서 다시
미세조정한다. ADR-0002는 "데이터·에폭·학습률을 단계적으로 올린다"만 정했고 "이전
시도를 이어받을지"는 코드가 암묵적으로 정한 것이었다 — 명시적 결정으로 바꾸는 작업.

## 2. 결정 경위

사용자에게 두 선택지(독립 재시작 유지 / 누적 학습 전환)와 각각의 트레이드오프를
제시(AskUserQuestion, 2026-11-25) — **"팀 동의 안 해도 돼"**로, 체크리스트가 원래
요구했던 "팀 합의"(W9-05 항목명) 없이 사용자 단독 결정으로 진행. 결과: **독립 재시작
유지**(권장안 채택).

## 3. 결정 및 근거

`docs/adr/0009-retrain-attempts-independent-restart.md` 작성. 핵심 근거:
1. 게이트가 거부한(BLOCK) 상태 위에 다음 시도를 쌓지 않음 — 원인 분석·신뢰성.
2. 에스컬레이션 표가 원래 "단일 변수 독립 비교" 구조 — 누적하면 효과가 뒤섞임.
3. ADR-0008(W9-04)로 GPU 지원이 들어와 "시간 절감" 명분이 약해짐.
4. ADR-0006(W9-03)이 이미 "마지막 에폭 과적합" 문제를 고쳐, 독립 재시작 자체가
   추가 위험을 만든다는 근거는 없음.

코드 변경 없음(동작 유지) — `src/etchpipe/retrain/loop.py::run_retrain_loop` 독스트링에
이 결정과 근거를 명시해, 다음에 코드만 보고 다시 조사하지 않도록 함.

## 4. 검증

동작 변경이 없어 회귀 테스트 대상 없음. 독스트링 수정 후 린트만 확인:

```
$ python -m ruff check src/etchpipe/retrain/loop.py
All checks passed!
```

## 5. 남은 사항

- 결정 근거 3(GPU로 시간 절감 명분 약화)은 W9-04와 같은 미확인 사항(별도 하네스
  실측 92.9배, 이 코드 경로로 재확인 안 됨)에 의존 — GPU 통합 실행이 재확인되면
  같이 재검증 필요[미확인].
- 결정 근거 1·2는 아직 실제 경계 사례(시도 1이 게이트 통과선에 거의 근접했던 경우)로
  검증된 바 없음[제안] — 그런 사례가 실제로 나오면 이 결정을 재검토할 근거가 된다.
