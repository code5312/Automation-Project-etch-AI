## 판단 기준: "잘 학습됐다"고 볼 수 있는 지표 조합 [제안, 설계서 C4/C5 근거]

아래는 생각나는 대로의 기준이 아니라 `docs/project-design.md` C4(평가)·C5(회귀 게이트)와
체크리스트 W5-01이 이미 정의한 지표를 그대로 따른 것이다. 지금 우리가 본 건 이 중
일부(④)뿐이다.

1. **train/val loss 동반 하락, val이 뚜렷이 벌어지는 지점 없음** — 과적합 없음의 1차 신호.
   지금 train_main.py가 val을 전혀 안 봐서 **이 항목 자체가 비어 있음**(문제 ①).
2. **val 롤아웃 Chamfer *와* 깊이오차가 베이스라인(a)(b) 둘 다보다 낮음** — 지금 Chamfer는
   통과, 깊이오차는 실패(문제 ②). "잘 학습됐다"는 최소 둘 다 통과해야 한다.
3. **스텝 5·10·20별 오차 추이**(C4 지표, 체크리스트 W5-01) — C5 규칙④ "롤아웃 후반 오차
   급증 없음"을 실제로 보려면 최종 스텝 하나만 볼 게 아니라 중간 스텝도 봐야 한다.
   **지금은 최종 스텝만 보고 있다** — 중간 스텝 수치가 없음.
4. **골든셋 10개(중심5·경계3·극단2) 평균 Chamfer ≤ 격자 1칸 수준**(C5 규칙①) — 아직
   한 번도 돌려본 적 없음(W5 항목). val 40개 평균과 크게 다르면 골든셋이 대표성이 없거나
   모델이 특정 지오메트리에서만 약하다는 뜻.
5. **IoU, CD_top/mid/bot, taper, bowing**(C4 지표, W5-01) — Chamfer·깊이오차만으론 못 잡는
   실패 모드(모양 뒤틀림, 입구/바닥 오차 구분, 측벽 경사)를 구분한다. 아직 구현 전.
6. **OOD 20개 오차 / val 오차 비율**(C4 "OOD 오차 비") — 학습 범위 밖에서 얼마나 깨지는지.
7. **추론 시간**(C5 규칙⑤) — 정확도와는 별개 축, 서빙 가능한 속도인지.
8. **직전 챔피언 대비 평균 오차 악화 ≤10%**(C5 규칙③) — 아직 챔피언이 없어 해당 없음,
   두 번째 재학습(W6 드리프트 루프)부터 의미 있음.

## 위 지표들의 "값 자체"가 암시할 수 있는, 아직 안 적힌 문제들 [제안, 추가 조사 전]

지표를 실제로 계산해보면(위 1~8 채워지면) 다음 패턴이 각각 다른 문제를 가리킬 수 있다 —
미리 적어두는 가설이며 실측 전까지는 [미확인]이다.

- **스텝별 오차가 초반엔 작다가 특정 스텝부터 급격히 커짐** → `rollout.py`의 법선·엣지
  재계산 누적 오차, 또는 특정 시뮬레이션 단계(마스크 완전 식각 등)에서 그래프 토폴로지가
  급변하는데 모델이 못 따라가는 것.
- **골든 10개 중 "극단 2개"에서만 유독 나쁨** → 정상 범위 안에서도 Θ 분포 끝단 쪽 학습
  데이터가 부족하거나 모델 표현력 부족(OOD가 아니어도 생길 수 있는 외삽성 문제).
- **IoU는 낮은데 Chamfer는 괜찮음** → 점들의 평균 거리는 맞는데 전체 윤곽(마스크 영역)의
  위상이 틀어짐(구멍, 끊어짐 등) — Chamfer가 못 잡는 실패 모드.
- **taper/bowing 오차만 유독 큼** → 깊이 방향은 맞는데 측벽 프로파일(경사·볼록)을 못
  맞춤 — 엣지 특징(법선 등)의 학습 신호 부족 의심.
- **CD_bot만 유독 나쁨** → run당 K스텝 중 마지막(바닥 근처) 스냅샷의 비중이 작아 학습
  신호가 약했을 가능성 — 전이쌍 샘플링 가중치 재검토 여지.
- **OOD/val 오차 비율이 폭발적으로 큼(수십 배)** → 정규화 통계(`node_mean/std`)가 학습
  범위 안에서만 맞게 계산돼 있어 범위 밖 입력이 정규화 후 극단값으로 튐 — robust
  scaling/클리핑 검토 여지.
- **추론 시간이 기준 초과** → `processor_size=6`이어도 노드 수가 큰 레시피에서 느릴 수
  있음 — 레시피별 노드 수 vs 추론 시간 상관관계 확인 필요.
- **(W6 드리프트 재학습 때) 챔피언 대비 악화 ≤10% 위반** → fine-tuning 에폭이 너무 적어
  과소학습, 또는 너무 많아 드리프트 데이터에만 과적합(일반 val은 악화) — 지금 "val 추적
  없음"(문제 ①)과 같은 구조가 재발할 위험이 가장 크다.

## 열린 문제 (미해결)

### 1. val 기준 체크포인트 선택이 없음 — 과적합 의심 [미확인, 우선순위 높음]

`train_main.py`(W4-04)는 매 에폭 `ckpt_last.pt`를 덮어쓰기만 하고 val 평가를 전혀 안 한다.
그 결과로 보이는 현상:

| | Chamfer 중앙값 | 깊이오차 중앙값(µm) |
|---|---|---|
| 모델 A — 초안(팀원 제공, epoch=5, **미수렴**) | 1.335 | 1.119 |
| 모델 A — 본 학습(epoch=99, train loss 0.031) | **2.383** | **2.521** |

train loss는 본 학습이 훨씬 낮은데 val 롤아웃 성능은 거꾸로다 — train/val 괴리(과적합)
신호로 보이지만, 초안이 정확히 어떤 조건으로 학습됐는지 몰라(문제 ④ 참고) 완전히 공정한
비교는 아니다.

- 참고: 팀원 FNO 초안은 "val 40런은 에폭 고르는 데 사용"한다고 명시
  (`runs/fno_draft/README.json`) — MGN 쪽만 이 장치가 빠져 있었다.
- **코드 수정 완료(2026-11-10) [확인], 재학습·재평가는 아직 [미확인]**: `train_main.py`에
  val 평가(`loop.evaluate`, teacher-forcing, `torch.no_grad()`) + `ckpt_best.pt`(val 기준
  최소 손실) 저장 추가 — 증거: `reports/evidence/W4-04_train_main_wiring.md` "업데이트
  (2026-11-10)". 아직 이 코드로 **다시 학습을 돌려보지 않았다** — 재학습 후 `ckpt_best.pt`
  를 `run_rollout_comparison.py`로 평가해 `ckpt_last.pt`(epoch=99, 과적합 의심)와 실제로
  비교해야 이 문제가 해결됐는지 확인된다.

### 2. 깊이오차가 단순 베이스라인(b)보다 나쁨 [확인]

본 학습 체크포인트: 깊이오차 중앙값 **2.521µm** vs 베이스라인(b, 깊이 MLP 외삽)
**1.910µm**. D4 판정 기준(Chamfer)은 통과하지만, 전 지표에서 베이스라인을 이기는 건
아니다.

- 해석 후보(미확인): Chamfer loss는 점 집합 전체 모양을 맞추는 데는 강하지만 깊이
  방향 정밀도를 직접 벌점 주지 않는다 — loss 구성 재검토가 필요할 수 있음(가중치 추가 등,
  사용자 확인 후).

### 3. val run별 오차 분산이 크고 두 지표가 다른 실패를 잡는 것으로 보임 [확인, 패턴 미분석]

- Chamfer: 0.46(`r0325`, 최선) ~ 3.81(`r0326`, 최악) — 약 8배 차이.
- 깊이오차: 0.13(`r0335`) ~ 9.74(`r0326`) — 약 75배 차이.
- **`r0326`은 두 지표 모두 최악** — 공통 실패 사례로 먼저 들여다볼 후보.
- **`r0335`는 반대 패턴**(Chamfer는 3번째로 나쁜데 깊이오차는 전체 중 최고) — 모양(타퍼·
  바우잉 쪽)은 틀렸는데 깊이는 맞춘 경우로 보임. Chamfer와 깊이오차가 서로 다른 실패
  모드를 잡고 있다는 신호.
- **다음 조치(미착수)**: `r0326`/`r0335` 등 극단 사례의 레시피 파라미터(Θ)를
  `data/raw/<run_id>/meta.json`에서 뽑아, 특정 파라미터 영역(예: `ion_flux` 극단값)에서
  유독 못하는지 확인.

## 해결된 문제 (히스토리, 참고용)

1. **`processor_size` 오판**: 체크포인트의 `processor_layers` 12개를 보고
   `processor_size=12`로 잘못 바꿨다가, physicsnemo가 edge_block·node_block을 번갈아
   쌓아 레이어 수가 `2*processor_size`임을 확인하고 6으로 정정
   (`reports/evidence/W4-06_rollout_vs_baseline.md`).
2. **인코더/디코더 `hidden_dim_*` 미전달**: `MeshGraphNetModel`이 `hidden_dim_processor`만
   넘기고 `hidden_dim_node_encoder`/`hidden_dim_edge_encoder`/`hidden_dim_node_decoder`
   (기본값 128)를 안 넘겨 체크포인트(전부 64) 로드가 실패하던 문제 — 같은 문서.
3. **입력 정규화 누락**: CPU 과적합 프로브가 정규화 없이 돌아 손실이 0.75대에서
   plateau — `NodeEdgeNorm` 추가로 해결(커밋 `3dac7d7`).
4. **체크포인트 키 접두사 불일치**: `train_main.py`가 `MeshGraphNetModel` 래퍼 전체를
   저장해 키에 `net.`이 붙는데, 비교 스크립트(`_load_model_a`)는 팀원 원본(접두사 없음)
   형식만 가정하고 있었음 — 2026-11-10, 두 형식 다 지원하도록 수정.
